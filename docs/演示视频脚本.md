## Part 2：开发过程（匹配开题报告，约 7 分钟）

### 【镜头 7】技术选型与系统架构（约 1.5 分钟）

> 画面：画中画全屏（或切 VS Code 显示项目结构）

**口播**：
开发部分我按开题报告的三个层面来讲：技术选型、系统架构、核心算法。

技术栈是前后端分离三段式：后端 Spring Boot 3 + MyBatis-Plus + MySQL 8.0，前端 Vue 3 + Element Plus + Vite，算法服务独立部署用 Python FastAPI。为什么算法单独拆？因为路径规划计算量大，Python 在科学计算上生态更成熟，而且拆成微服务后可以独立扩容。

整体架构分五层：展示层（Vue 页面）、API 网关（Nginx 转发）、业务层（Spring Boot 控制器+服务）、算法层（FastAPI 四个算法）、数据层（MySQL + CSV 演示数据）。

> 动作：（可选）画中画手持平板展示架构图，或屏幕共享 VS Code 的 backend/src + frontend/src 目录树

### 【镜头 8】核心算法实现（约 3 分钟）

> 画面：切到 algorithm/app/algorithms/astar.py 代码，画中画在角上

**口播**：
算法部分对应开题报告里的四类方法。论文第 5 章详细推导了数学模型，实现上主要在四个文件里：

baselines.py 放贪心和最近邻，一步只看当前最近点，速度快但航程偏长；
ga.py 是遗传算法，把访问顺序编码成染色体，迭代几百代后收敛到好解；
aco.py 是蚁群算法，信息素+启发因子共同决定下一步，多轮后短路径被强化；
astar.py 是论文的重点——标准 A* 改了三处：第一，启发函数加了 1.5 倍权重让搜索更朝终点冲；第二，斜向移动时检查相邻格子防止从禁飞区角上擦过去；第三，搜完后做视线平滑，能直拉的拐点全部拉直。论文第 6 章实验表明，改进 A* 比标准 A* 少扩展 83.6% 的节点，拐点砍了 90.2%，耗时从 16 秒降到 1.5 秒。

> 动作：鼠标滚动展示关键代码段（加权启发那行、视线平滑函数）→ 切到 aco.py 滚动 2–3 行信息素更新 → 切到 ga.py 滚动 2–3 行交叉变异
